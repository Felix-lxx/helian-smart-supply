# 禾链智配 · 系统升级交付说明

本次已直接升级现有 Vue + Django 项目，延续农产品电商业务，新增批次、采购需求、分货方案和跨端履约。此前《三创赛常规赛_定位与升级建议》是研究建议；本文件列出实际交付与当前边界。

## 使用入口

- 前端：http://127.0.0.1:5173；后端：http://127.0.0.1:8000/api/。
- 登录页提供采购端、供应端、运营端三个演示入口，仅 Django DEBUG 模式开放。演示账号和记录有明确标记，不代表真实成交、实测收益或第三方认证。
- 工作区角色分别为采购商 retail、供应商 supplier、管理员 admin；后端逐操作验证权限，前端导航只是交互辅助。
- 以后启动：在项目根目录执行 `powershell -ExecutionPolicy Bypass -File .\启动系统.ps1`。可选 `-SeedDemo` 初始化缺失的演示记录，不重置已有记录。脚本保留已占用端口的进程，不强制终止其他服务。
- MySQL 需先运行。后端依赖位于根目录 `.venv`，前端依赖位于 `code/Agricultural-product-system/node_modules`。本地虚拟环境使用当前电脑已安装的 PyTorch、SciPy 等运行库，迁移电脑时需重新安装。

## 真实联动

1. 新批次默认待复核；放行才计入可售库存。隔离后立即退出可售与分货候选，关联订单收到通知，并禁止发运。
2. 下单事务锁定批次并预留库存。重复提交同一请求返回原订单；取消及超时未付订单释放预留。发运同时扣减实物数量与预留数量，避免再次销售同一份货。
3. 买家提交付款参考信息，供应商核对后才能发运。买家按数量验收，差异进入异常状态；供应商提出方案，买家确认后结束，保留事件记录。
4. 分货试算不占库存；方案保存时由服务器重新计算。发送方案生成采购报价，买家接受后才预留库存并创建订单。部分承接保留需求余量，避免重复覆盖。
5. 所有写操作完成后重新拉取数据，其他已打开工作区在可见时每 20 秒刷新。消息带业务入口，买卖双方均有对应待办。设备页独立刷新。

## 可交互、可量化的特色

- **规格匹配矩阵**：按品种、单位、尺寸、等级、包装、预算、交期、抽检条件逐格解释可配/不可配原因。
- **有约束分货**：SciPy 混合整数规划，约束库存、需求上限、单位和最小起订量。先最大化可分配数量，再在该覆盖量下最小化采购金额。数量不同单位分开求解，金额不含运费。
- **抽检证据模式**：展示样本数、缺陷数、观察比例及 95% Wilson 区间；可切换观察比例和区间上界筛选，直观看到更保守条件下的覆盖差异。该区间只针对所记录抽样指标，不等同食品安全检测或整批质量保证。
- **库存扰动试算**：调低某个批次可用量后重新计算，展示覆盖需求、金额、变更连线数与实际耗时。当前采用完整重新求解，不声称已实现增量优化算法。
- **分货桑基图**：同单位绘制数量宽度，悬停看值，点击连线看批次、需求、单价与金额，再切换精确明细。
- **地图找货**：坐标来自商品资料；未知坐标不补造。同坐标货源聚合，点击产地点筛选右侧货源，可缩放与拖动。散点不是车辆实时位置。

以上使用现有统计方法与优化求解器完成业务组合，未将其宣称为原创算法。竞赛可通过真实采购数据比较人工分货、基础匹配、保守证据模式的覆盖率、时间和验收差异；当前演示对比不能替代实证结果。

## 当前边界

- 付款与异常处理是人工核对和协商记录，未接支付网关、银行核验、自动退款或会计结算。
- 物流展示真实填入的承运方、单号和事件，未接第三方轨迹、车辆定位或路径优化。
- 视觉辅助调用项目已有权重，保留检测图片与记录，需人工填写抽样数并复核，模型不自动决定食品品质与放行。
- 设备接收要求后端与设备均配置环境变量 `DEVICE_INGEST_TOKEN`，设备请求头传 `X-Device-Token`。`code/mock_x5.py` 仅是明确标记 MOCK 的随机遥测联调工具，不运行模型；默认没有启动或填充设备数据。
- AI 助手只解释当前权限内摘要；已有 DeepSeek 配置可用时调用，失败则返回业务记录摘要，不执行交易。
- 历史订单没有真实数量的记录保持未知，不从金额倒推出数量；新订单保存批次、数量和规格快照。
- 当前为本地开发交付。正式对外部署需关闭 DEBUG 与演示入口，并配置生产数据库、静态媒体存储、域名 HTTPS 和对应真实业务服务。
