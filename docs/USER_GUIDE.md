# 集采与履约操作指南

本轮在原 Vue / Django / MySQL 项目中增量实现，不替换原数据库。新增迁移为 `0023_businesssite_coordinate_source_and_more`，启动脚本会执行迁移；`-SeedDemo` 会补充明确标识的演示数据，不重置已有操作。

## 页面与业务

| 页面 | 可以完成的操作 | 关联对象 |
| --- | --- | --- |
| `/control` | 按到货日、单位及站点查看真实约定量、缺口、发运、任务与异常，点击进入业务记录；地图选择站点后筛选业务 | 采购需求、订单、分配、任务、站点、业务事件 |
| `/purchase-plans` | 建立多门店多品项集采单，复用模板，导入 CSV，核对净量反算，查看报价和订单 | 采购单、需求明细、企业、站点、报价、订单 |
| `/procurement` | 用途和加工方式筛选、净需求反算毛料、成本比较、查看称重依据、生成采购草稿或加入清单 | 批次、独立用途称重记录、阶梯与批次价、采购清单 |
| `/cart` | 核对采购明细、选择收货站点、到货日、结算方式和数量允差，重新核价后提交 | 采购清单、价格签名、站点、成交条款、预留库存 |
| `/grading` | 登记样本/整批用途称重，分级拆批、登记损耗与子批次价格；原批次扣减、子批次待复核 | 称重记录、分级记录、父子批次、库存流水 |
| `/workboard` | 领取、阻塞、分拣完成、发运/验收入口、任务搜索、扫码与下载标签 | 负责人、批次、订单、站点、实际发运与验收 |
| `/orders` | 完整记录分页与范围统计、分批发运、毛皮净称重、数量允差、合格与拒收、结构化处理 | 交易快照、实际履约方、发运、验收、处理单 |
| `/accounts` | 实重尾差确认、异议与补充依据、处理凭证、跨供应方供货款登记与到账确认 | 验收、实重对账、退款/补款、实际供货结算 |
| `/recovery` | 比较少改动、成本和交付方案，可选择其他已上架供货方，相关采购方与供货方共同确认 | 异常、原分配、替代分配、参与方、供货款与价差 |
| `/reviews` | 依据受影响采购量、预算、交期、区间和检查耗时排序，建立并完成复检任务 | 分项抽样、复检成本与耗时、受影响需求 |

## 关键规则

- 净量记录按“批次＋用途＋加工方式”区分。记录标识演示参数、样本估算或整批实称。净用量报价冻结依据；接受后按承诺净量计算剩余需求。箱、件不自动推断重量。
- 净采购毛料按起订量、包装增量向上取整。物理库存约束使用毛料数量，净需求覆盖使用用途净得率，不能把同一库存重复用于多个用途。
- 分级投入量等于所有子批次数量加损耗。预留库存不能拆出，子批次继承原品质证据，仍需复核后放行。子批次价参与核价及方案计算。
- 发运按实际供货方授权，登记合同数量及实际净重，扣减实际库存并释放对应合同预留。允差在下单时约定，不由供应方在发运时自行放宽。
- 实重验收不会仅因存在少量尾差就自动退款；先形成对账，交易供货方核对后生成退款或补款处理单，再由执行方登记凭证、接收方确认。
- 补发会产生独立发运、收货任务与验收，不能凭补发单号完成。退货接收进入隔离批次，不直接增加可售库存。全额退款释放尚未发运预留，保留已交付历史。
- 跨供货方补配保留交易责任方，新增实际履约方、对应任务和供货结算；实际替代方能查看并执行自己的履约。采购价差与供货方之间的付款分别保存，均需真实凭证。
- 编辑区使用独立表单，后台同步不覆盖在填内容；订单、任务和批次操作检查状态或版本。任务完成后同步关闭关联待办。

## 四个演示入口

登录页提供采购端、供应端、协作供货方和运营端。全部演示数据带演示标识。核心体验顺序：

1. 采购端查看集采单，进入用途采购，比较每净可用单位成本及称重依据。
2. 供应端进入分级与用途称重；登记依据后，采购端重新比较即可读取新记录。
3. 从订单收款确认进入作业任务，登记实际发运；采购端验收后，在对账中心处理实重差额。
4. 供应端登记批次异常并试算补配；参与方分别确认，处理供货款与价差后，由实际替代供货方发运。

## 地图、模型和资金边界

天地图密钥仅由服务端读取。保留底图版权，记录坐标来源与核对状态；未知坐标留空。在线底图失败自动显示随项目提供的行政区地图，图上虚线表示业务关联。未接入定位和道路服务，因此不展示车辆实时位置或导航路线。

复检排序属于透明规则，分配与补配使用已有 SciPy/HiGHS 混合整数规划，Wilson 区间仅说明代表性外观抽样的不确定性。本轮未宣称原创统计方法、固定收益提升或检测准确率。图像模型与外部助手仍按可选配置调用。

本项目记录付款、退款和双方确认，不代替支付机构划款。电子秤、打印机、车辆定位目前通过人工记录和标准业务对象预留接入位置，未接真实设备时不模拟设备观测。

## 必要验证

本轮使用内存数据库完成增量迁移及角色接口检查，并验证净量报价、分级守恒、分拣发运、实称验收、实重异议和差额处理、独立补发验收、跨供货方补配及实际发运；不改写用户业务数据。前端执行生产构建，并按桌面及手机尺寸集中检查主要页面。
